# Trace analysis capabilities

**This table is the single source of truth for trace analysis capability claims in this repository.**

Scope: features present in the inspected `main` branch on 2026-11-07. Draft or unmerged pull requests are not counted as implemented. A feature marked **Partial** may display only evidenced input and must not infer missing events, timestamps, ownership or resource usage.

Here **Validated against real hardware** means that the complete named analysis feature was checked with physical target trace input. Generic firmware builds, installed UI smoke tests and the previously observed MSPM0 RAM CTF capture do **not** establish that validation for the listed analysis views. `No` on the licensing/IDE rows means hardware validation is not applicable, not that the license or Eclipse components are absent.

| Feature | Status (Implemented / Partial / Not implemented) | Data source | Known limitations | Validated against real hardware (Yes / No) |
| --- | --- | --- | --- | --- |
| Thread state timeline | Partial | Saved Zephyr CTF; [semantic parser](../plugins/io.github.niwantha33.zew.ui/tools/rtos_analysis/semantic_trace.py), [interval builder](../plugins/io.github.niwantha33.zew.ui/tools/rtos_analysis/thread_timeline.py), [Eclipse view](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ThreadTimelineView.java) | Read-only interval table; Running, Ready, Blocked and Sleeping require observed boundaries; incomplete transitions remain Unknown; not a full-state graphical trace. | No |
| CPU load view | Partial | Saved CTF scheduler-derived intervals; [CPU calculator](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ThreadCpuLoad.java), [Eclipse view](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ThreadTimelineView.java) | Windowed per-thread Running percentages shown in a table, with ISR and idle summaries; Unknown intervals limit interpretation; not a live graph or hardware utilization measurement. | No |
| Custom tracepoint plotting | Partial | Saved CTF `named_event` samples and project `zephyr-tracepoints.properties`; [guide](USER_TRACEPOINTS.md), [Eclipse view](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/TracepointPlotView.java) | Timestamp/value table with min/max/mean, not a drawn time-series chart; only declared int32 or float32 samples are interpreted. | No |
| Priority inversion detection | Partial | Saved CTF mutex, scheduler and explicit thread-priority events; [contention guide](CONTENTION_REPORT.md), [Eclipse view](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ZephyrContentionView.java) | Reports only evidenced low-priority mutex holder, blocked higher-priority waiter and intervening medium-priority execution with numeric priorities; does not prove a missed deadline. | No |
| Long resource contention detection | Partial | Saved CTF mutex/semaphore transitions; [contention guide](CONTENTION_REPORT.md), [detector](../plugins/io.github.niwantha33.zew.ui/tools/rtos_analysis/contention_detector.py) | Only bounded, observed waits strictly greater than a user threshold are reported; holder is omitted without proven ownership; incomplete waits are not timed. | No |
| Memory allocation profiling | Not implemented | [Semantic event declarations](../plugins/io.github.niwantha33.zew.ui/tools/rtos_analysis/semantic_trace.py) only in the inspected main branch | No memory-profile view or verified native Zephyr malloc/free/slab-size mapping on main; an unmerged implementation proposal is not counted. | No |
| Live streaming | Not implemented | [Saved RAM CTF snapshot workflow](TRACE_COMPASS_INTEGRATION.md) only | No live or incremental CTF stream-to-analysis integration; captured snapshots are offline. | No |
| Custom trace event injection | Not implemented | [Manual application event guide](USER_TRACEPOINTS.md) only | Firmware authors add Zephyr `sys_trace_named_event` calls themselves; Workbench does not insert instrumentation or modify application source. | No |
| Hardware validation breadth | Partial | [RTOS analysis roadmap](RTOS_ANALYSIS_ROADMAP.md) and [Trace Compass handoff](TRACE_COMPASS_INTEGRATION.md) | An MSPM0 RAM CTF capture was observed; no repeatable cross-vendor physical-hardware validation matrix for these analysis views is recorded. | No |
| Licensing model | Implemented | [Repository Apache-2.0 license](../LICENSE) | Open-source licensing is established by the license file; this is not a claim about analysis completeness. | No |
| Runs inside the IDE | Partial | Native Eclipse [Thread Timeline](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ThreadTimelineView.java), [Tracepoint](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/TracepointPlotView.java), and [Contention](../plugins/io.github.niwantha33.zew.ui/src/io/github/niwantha33/zew/ui/ZephyrContentionView.java) views; [Trace Compass handoff](TRACE_COMPASS_INTEGRATION.md) | Native offline tables run inside Eclipse; full Trace Compass timeline viewing uses an optional external application or separately installed plug-ins. | No |

Changes in these claims must be accompanied by changes to this document and by concrete evidence. See also [RTOS analysis roadmap](RTOS_ANALYSIS_ROADMAP.md) and [trace capture limits](TRACE_COMPASS_INTEGRATION.md).
