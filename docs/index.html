HOW IT CONNECTS

From selected board
to defensible evidence.

An engineering path, not a promise of automatic hardware verification. Every stage keeps its input and qualification boundaries visible.

  1. 01

    Select

    Choose project, board, SoC and profile.

  2. 02

    Configure

    Examine Kconfig and Devicetree requests.

  3. 03

    Build

    Collect .config, zephyr.dts and ELF evidence.

  4. 04

    Inspect

    Flash or debug only where the runner and probe support it.

  5. 05

    Investigate

    Review saved traces, logs and provenance offline.

Principle: discovered ≠ built ≠ flashed ≠ debugged ≠ physically validated.

GOOD TO KNOW

Built openly.
Documented carefully.

Is Zephyr Eclipse Workbench free to use?

The original project code is published under Apache-2.0. Eclipse, Zephyr and third-party vendor tools have their own licenses and requirements; review the repository's licensing guidance.

Does it work with every microcontroller?

No universal flash/debug claim is made. Board discovery follows the Zephyr checkout; actual build, peripheral, runner, probe and debug capabilities require validation for the exact target and setup.

Are RTOS metrics live measurements?

The described CPU, contention, memory and timeline views use saved CTF evidence. They do not promise live streaming, calibrated CPU utilisation, full trace coverage or measured WCET.

Is this ready for production certification?

No. The current published releases are development previews and Evidence Engine release gate G0 remains open. Review the current status and compatibility evidence before relying on any feature.
