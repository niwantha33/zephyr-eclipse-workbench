Comparison date: **2026-11-07**. This is a capability-level documentation comparison, not a performance benchmark or a claim that either tool has been tested under identical workloads. ## How to read this table

Zephyr Eclipse Workbench is an **open-source, Eclipse-IDE-integrated, offline analyser** built on saved Zephyr CTF evidence and an optional Trace Compass handoff. Tracealyzer is a **commercial product** with broader published hardware/transport coverage and more mature trace visualization; it has wider documented Zephyr support, although an exact hardware-validation count is **not verified** here. **The two are not equivalent today.** A `Partial` Workbench entry establishes only what the linked repository capability record describes, not full parity with Tracealyzer.

## What we would need to close the gap

1. **Make offline capture and evidence-quality diagnostics more reliable across truncated/lost CTF inputs** — effort: **medium**.
2. **Validate existing timeline, CPU, tracepoint and contention results on physical MSPM0 and additional Zephyr SoC/probe combinations** — effort: **large**.
3. **Implement an opt-in live CTF streaming pipeline with backpressure, reset recovery and loss indicators** — effort: **large**.
4. **Add actual linked plots for time-series values and CPU load rather than tables alone** — effort: **medium**.
5. **Complete Zephyr memory allocation profiling from verified pointer/size/slab events, withholding unsupported byte totals** — effort: **medium**.
6. **Extend and hardware-check resource wait, priority and ownership analysis across Zephyr releases** — effort: **large**.
7. **Provide optional source-level guidance or snippets for custom user-event instrumentation, without silently modifying firmware** — effort: **small**.
8. **Qualify long-duration and SMP capture, clock conversion and multi-stream accounting** — effort: **large**.
